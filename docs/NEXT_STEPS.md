# 下一批开发任务

更新日期：2026-10-15。以下都是未实施任务，可直接拆成 GitHub Issue 或小规模 PR。任务依据当前源码与本次检查；此前构建通过和故障模拟结果不能视为修复后的验收结果。

总方向见 [ROADMAP](../ROADMAP.md)，数据模型、加密与迁移约束见[内容扩展设计](superpowers/specs/2026-10-15-personal-content-hub-design.md)。任务按验收条件关闭，完成后同步更新文档状态。

**当前执行主线已更新为[五彩与 GoTab 替代实施路线](REPLACEMENT_PLAN.md)。** 本文 N 系列保留为通用底座任务；Chrome / Edge 扩展、网页标注、设备同步和 Obsidian 插件使用 R 系列分批交付。先复用 N01–N03、N06、N04，插件不再等待全部项目资料和附件功能完成后才开始。

## 推荐执行顺序

`N01 → N02 → N03 → N06 → N04 → N05 → N07 → N08 → N09 → N10`

N01–N03 先保护现有内容，N06 修正常用编辑与定位；N04–N05 建立可扩容底座；N07–N08 交付优先内容；N09–N10 扩展附件与多端。任务编号用于引用，执行顺序以上述依赖为准。每批只引入必要依赖，默认保持现有部署方式。

## N01 · 凭证保护与锁定清理（M0）

**涉及**：`src/lib/crypto.ts`、`src/lib/aiParser.ts`、`MasterKeyModal.tsx`、`SecretCard.tsx`、`AiIngestModal.tsx`。

- [ ] 默认不记住主密码，移除现有明文设备会话；迁移不能先丢失旧内容的解密能力。
- [ ] 凭证名称、说明、标签生成前脱敏；历史可疑说明字段在解锁后预览并清理。
- [ ] 锁定清除已展示明文、搜索摘要和解密缓存；忽略锁定前启动的异步解密结果。
- [ ] 锁定时清理相关编辑器中的敏感输入；取消操作不把原文写入普通草稿。

**验收**：使用已知测试凭证扫描持久化数据，没有主密码或完整凭证副本；展开后锁定立即隐藏；解密尚未完成时锁定也不会重新显示。锁定并不是对正在运行的同源脚本攻击的防御承诺。

## N02 · 保存失败与备份结构校验（M0）

**涉及**：`src/lib/storage.ts`、`src/App.tsx`、`SettingsModal.tsx`。

- [ ] 保存返回可处理的结果；配额不足、权限异常和序列化失败会提示原因与恢复方式。
- [ ] 内存中新编辑内容保留，并支持临时导出，不显示已持久化。
- [ ] 备份增加格式版本；所有必填集合、条目类型、时间、ID 和引用接受运行时校验。
- [ ] 导入前展示数量与替换范围，保留导入前快照；非法文件不写入当前存储。

**验收**：拒绝 `sites: {}`、缺失集合、重复 ID、未知且无法迁移的版本；模拟写入失败后仍能导出当前内容；非法备份前后原数据一致。

## N03 · 加密备份与恢复解锁（M0）

**涉及**：`src/lib/crypto.ts`、`src/lib/storage.ts`、`SettingsModal.tsx`、配置存储调用点。

- [ ] AI、OSS、五彩及有道等敏感配置纳入加密；显示脱敏摘要，解锁后才能使用对应能力。
- [ ] 完整备份默认整体加密，包含敏感内容、配置、版本、KDF 参数、salt、IV 及完整性校验所需信息。
- [ ] 恢复时验证备份密码，处理目标浏览器已有不同主密码的情况。
- [ ] 旧格式明文备份仅作为显式兼容导入，导入后转为新格式；普通 Markdown 导出与完整加密备份分开命名。

**验收**：干净浏览器正确恢复笔记、收藏、测试凭证与手绘；错密码、篡改、已有其他主密码均有明确处理；错误文件不会覆盖现有验证信息。

## N04 · 存储访问层与 IndexedDB 迁移（M1）

**涉及**：`src/lib/storage.ts`、`src/types/index.ts`、`src/App.tsx`；建议新增 `src/data/`。

- [ ] 把保存整份 HubState 的调用收敛为按条目读写、列表查询和事务接口。
- [ ] 分开保存目录、正文、附件记录、Blob、加密配置及待同步操作。
- [ ] 同一事务记录内容变更与待同步操作；旧 UI 可通过适配层渐进接入。
- [ ] 迁移旧 ID 与时间，手绘 Data URL 转 Blob，保留分类、标签与关联。
- [ ] 迁移版本、核对报告、失败重试和回滚入口完整；未确认前不删除旧副本。

**验收**：重复迁移不重复数据；中断可重试；升级失败可回退；单条编辑不读取或重写其他附件；多标签页不会把旧整包状态覆盖回来。

## N05 · OSS 真实读写与覆盖保护（M1）

**涉及**：`src/lib/s3Client.ts`、`DataInteropView.tsx`、配置模型。

- [ ] 修正浏览器签名路径，复用经过验证的浏览器 SDK；区分凭证错误、无权限、网络和跨域问题。
- [ ] 选择笔记时加载正文，已修改的远端内容使旧缓存失效；加载失败时禁止保存覆盖。
- [ ] 列表按游标取完需要的页面；显示真实空列表，不回填示例数据。
- [ ] 上传、删除、刷新返回明确结果；本地保存和云端确认分别展示。
- [ ] 未验证原生对象条件更新能力前，编辑先生成独立恢复副本；多端使用独立 revision，不能把“先读 ETag 再无条件写”当成原子防冲突。
- [ ] 稳定联网写入前明确只读 / 可写权限；稳定附件上传前使用受保护的临时授权服务，长期云密钥保留在服务端。

**验收**：403、超时、空列表、超过 200 个对象、新笔记正文和缓存变更均处理正确；云端删除失败保留本地项与重试信息；真实写权限联调使用专用测试前缀。

## N06 · 笔记编辑、搜索定位与移动端修复（M0）

**涉及**：`NotesView.tsx`、`GlobalSearch.tsx`、`Navbar.tsx`、`src/App.tsx`、`wucaiClient.ts`。

- [ ] 用编辑条目的 ID 区分新建与更新，改标题保持原 ID。
- [ ] 普通草稿定期保存；切换条目、关闭页面或异常退出后可恢复。
- [ ] 搜索结果携带类型和 ID，定位到具体笔记、项目或远端正文；加载失败保留结果与重试入口。
- [ ] 同页高亮按稳定来源 ID 导出，重复操作合并或跳过，不互相覆盖。
- [ ] 390px 手机宽度可访问搜索、新增和菜单；其他操作收进菜单，常用按钮可方便点按。

**验收**：改名不会增加条目数；第二条笔记的搜索结果打开第二条；同页两条高亮都保留；手机上设置与导航入口完整可见。

## N07 · 收件箱、笔记与收藏（M2）

**依赖**：N04、N06；发布真实敏感内容录入前完成 N01–N03。

- [ ] 收件箱先保留普通原文，记录来源与状态；敏感输入直接进入金库加密流程。
- [ ] 支持从收件箱转成笔记或收藏，选择标签、主题集合和项目。
- [ ] Markdown 渲染保留源码，默认不执行导入 HTML；普通链接仅允许明确支持的协议。
- [ ] 收藏可编辑；HTML 书签导入前预览；规范化 URL 生成去重候选，不盲目移除业务参数。
- [ ] 统一分页、标签、置顶、归档、回收站及批量操作，保留导入来源和处理记录。
- [ ] 普通条目可导出为开放格式，导出范围清楚可见。

**验收**：粘贴 → 保存 → 整理 → 搜索定位 → 编辑 → 导出完整走通；重复导入不会无提示生成多份；断网不丢输入。

**依赖**：N07；使用 N04 的统一目录和关联能力。

- [ ] 项目保存名称、说明、状态、仓库、主页与可选时间。

- [ ] 增加 README 式说明、需求记录、部署手册与决策记录模板。
- [ ] 项目归档保留全部资料，删除项目先解除或保留关联，不能级联删除共享资料。
- [ ] 导出项目说明、资料清单与可读内容，明确附件是否已包含。

**验收**：一个真实使用方式的测试项目可关联两篇笔记、两个链接和一台服务器；项目改名、归档、恢复后关联不变；共享资料不会因项目删除丢失。

## N09 · 附件与批量导入（M3）

**依赖**：N04、N05、N08。

- [ ] 图片、PDF 与普通文件保留原件，目录记录 MIME、大小、校验值和引用；预览为可选派生物。
- [ ] 附件本地落盘后才显示已保存；文件目录引用更新与 Blob 保存保持一致。
- [ ] 稳定的附件 ID、私有对象前缀、上传进度和重试记录；确认远端校验前不清理唯一原件。
- [ ] 导入支持预览、重复检测、逐项错误报告、按批撤销；失败文件可单独重试。
- [ ] 大附件按产品限制处理；完整导出用 Blob / 文件流或适合的打包方案，避免超大 Data URL。

**验收**：笔记 / 项目能关联并下载图片与 PDF 原件；同名不同文件都保留；上传失败和撤销不留下不可解释的悬空引用；清理缓存不删唯一原件。

## N10 · 增量同步、冲突与恢复演练（M3）

**依赖**：N03、N04、N05、N09。

当前完整替代版按 R3 的 API / D1 同步方案实施。本任务的附件部分随 N09 验收，结构化资料同步可先于大附件完成。

- [ ] 每次变更生成独立 operationId、revisionId、parentRevisionIds；上传重试幂等。
- [ ] API 用事务记录独立版本、幂等操作和变更游标；OSS 保存附件与备份，不作为第二份结构化数据权威来源。
- [ ] 相同父版本的分叉保留双方，用户选择或合并后生成新版本；删除保留可恢复标记。
- [ ] 附件完成上传后再发布资料的云端可用状态，失败操作留在队列。
- [ ] 备份与同步分别记录；在第二设备检查完整备份中的正文、附件与关联。

**验收**：两设备离线修改同一笔记保留两份；重复上传不复制条目；删除与离线旧设备重连不会静默复活；从完整备份恢复的抽样文件校验值一致。

## 最少但有价值的检查

- 每批运行 `npm run build`；文档修改只检查链接和差异，不为文档重复构建。
- 存储 / 迁移 / 备份任务覆盖坏数据、配额不足、中断、重复执行、错密码和恢复回滚。
- 云端任务覆盖 403、超时、分页、正文缺失、离线重试和分叉版本。
- 界面任务检查桌面与手机，实际走通新增、编辑、搜索、归档、恢复及导出。
- 验收样本用占位凭证与专用测试前缀，记录数量和校验值，避免日志包含真实密钥。
