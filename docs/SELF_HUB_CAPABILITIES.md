# Self-Hub 能力与边界（当前交付状态）

更新：2026-10-19 ｜ 依据：P0–P2 的实施与自动化回归 ｜ 逐条证据见 [交接记录](SELF_HUB_PROGRESS.md)

这份文件回答一个问题：**现在能做什么、数据在哪里、哪些事不要期待**。它是给使用者与验收者看的能力清单，不是路线图；未实现的能力明确写在最后一节，不以「即将支持」的措辞出现。

## 1. 运行环境边界

| | 普通网页（`npm run dev` / 静态托管） | 浏览器扩展（新标签页 / 侧栏 / 打包应用） |
| --- | --- | --- |
| 数据位置 | 该 origin 的 `localStorage`（整包）+ IndexedDB（索引、镜像、v3 库） | 扩展 origin 的同名存储；**与网页版不共享** |
| 本地资料 / 收藏 / 项目 / 资源 / 提醒 / 签到 / 手绘 | 支持 | 支持 |
| 新标签页替换、对原网页划线 | 不支持 | 按浏览器权限支持 |
| 扩展内嵌的工作台页面 | — | 支持：`npm run package:extension` 把生产构建拷进 `extension/app/`，在真实扩展 origin 下可启动并保存（第 34 批新增用例）。**打包时会自检**：`index.html` 与 `dist` 一致、引用文件都存在；`--skip-build` 时若 `dist` 比源码旧则拒绝打包（第 35 批，避免装进过期工作台）。 |
| WebDAV / OSS 备份 | 需要目标允许跨域（CORS）；失败会给出诊断 | 扩展页具备 host 权限时可执行 |
| 浏览器关闭后继续备份 | 不承诺 | 不承诺（MV3 后台会被休眠，队列可恢复但没有常驻） |
| 多设备增量同步 | 未实现（P3） | 未实现（P3） |
| Obsidian 本地库自动写入 | 未实现（需插件，P3） | 未实现 |

**两个环境之间怎么搬数据**：导出「单个加密文件」→ 在另一个环境导入，走与恢复相同的预览/冲突流程（设置 → 数据与备份 → 跨环境交换）。**不会自动共享**。

## 3. 数据与备份

| 问题 | 答案 |
| --- | --- |
| 数据存在哪里 | 本机浏览器。**默认**是 `localStorage` 的 v2 整包；设置 → 数据与备份 可把事实来源切到 **v3 库（IndexedDB，按实体存储）**，切换前会先完整写入并确认。v2 负载在两种模式下都会继续写入，作为随时可回退的副本。**没有服务器**。 |
| 保存成功的依据 | `localStorage.setItem` 返回后才算成功；失败会明说「本次改动没有写入」。v3 路径以 IndexedDB 事务 `complete` 为准。 |
| 容量 | 默认（v2 模式）整包受浏览器 ~5 MB 限制，**超过 80% 会提前警告**（横幅 + 设置诊断行）。**切到 v3 模式后，整包只剩设备配置（几 KB），业务数据在 IndexedDB，不再受这条限制**；切换前的完整负载会留一份回退快照。 |
| 备份格式 | 两种并存：旧 `.selfhub/state.json`（整包明文，剥离连接密钥）与 v3 加密批次（`purpose`、清单、完成标记、逐对象哈希）。 |
| 迁移前的加密快照 | 写在 **IndexedDB**（`migration_snapshots_v3`），不占 `localStorage` 配额——否则「负载大到必须迁移」与「快照写不下」会互相锁死。旧版本留在 `localStorage` 的快照会在下次迁移时清除。**只保留最新一份**：快照约等于来源大小，多次迁移不会无限增长，代价是「上一次迁移之前」不可回滚。 |
| 备份包含什么 | 本机全部业务集合、已下载的手绘附件；**不含**连接密钥、设备信任材料、会话、Cookie、授权头、同步 token。远端未下载正文只登记引用（会明确写「引用备份」）。 |
| 金库条目 | 备份里是**密文**；恢复后仍需原来的金库主密码。备份密码 ≠ 金库主密码。 |
| 恢复能做什么 | 校验包 → 差异预览（两侧计数、冲突、缺失附件、未知字段、引用备份）→ 逐集合决定冲突（保留本机/使用备份/另存副本）→ 合并或替换 → 写回滚快照。**预览之后有编辑会被拒绝并要求重新预览**。v3 模式下恢复写入**活动库**（本机连接不被替换），旧格式导入与回滚走同一条路径。 |
| 换设备 | 可用「含凭据的加密迁移包」（独立目录、需二次确认、可删除）或「单个加密文件」；导入时逐服务判断：本机没配过 → 采用包里的整套配置+密钥；已配不同账号 → 跳过，不覆盖。 |
| 自动备份的触发 | 目的地、格式（旧/v3）、任务开关三者分开；只配 WebDAV 也会触发；v3 需要本次会话解锁备份密码，否则不运行也不上传。 |
| 备份的是哪个库 | 跟着 `activeLibraryId` 走：迁移切换之后，v3 备份/恢复/迁移包都指向**当前活动库**（第 25 批修掉的缺陷：此前会默认写向迁移前的 `local-v2`，备份看起来正常却不含新数据）。旧格式（legacy 整包）与活动库无关——**在 v3 模式下选旧格式会得到一份「成功但不含资料」的备份，因此自动备份被拦下、面板给出警告并提供一键改用 v3 加密备份**（手动仍可执行，警告始终可见）。 |
| 旧格式恢复在 v3 模式下 | 导入/回滚恢复的数据会**写入活动库**（保留本机连接），因此导入之后资料页真的能看到；写库失败时明确提示「没有写入」，不会再先弹成功。 |
| 保留策略 | 最近 10 次 + 最近 30 天每日一份；只清理本设备 v3 目录，保护指针批次，只剩一个可用备份时拒绝清理；迁移包不参与清理。 |

## 4. 明确未实现（请不要期待）

1. **切库可切换，默认仍是 v2**：设置 → 数据与备份 →「存储模式」可以把事实来源切到 v3 库，流程是**带校验的迁移**：输入备份密码 → 先写一份加密快照 → 分批写入暂存库（可续跑）→ 校验计数与引用 → 原子地切换 `activeLibraryId`（应用随后跟着该指针读写）。**切换期间按钮禁用并显示进度**；重复点击不会启动第二次迁移（第 32 批修掉的缺陷：连点会跑两次迁移并丢掉第一份快照）。失败时不改动任何东西。切换以**实时负载为准**（IndexedDB 镜像只用于补空集合，避免记录翻倍）；v3 模式下负载只写设备配置（**5 MB 上限因此解除**），切换前的负载留一份回退快照；库被清空时启动会从快照恢复；切回 v2 会把库重新物化（装不下就拒绝并提示先导出）。**但**：没有多库 UI（只有迁移产生的暂存库 id）、切换后旧库与快照不自动清理、扩展环境的 IndexedDB 配额未实测、`MIGRATION_SWITCH_ENABLED` 常量仍为 false（UI 用显式开关）。
2. **多设备同步**：没有服务端、没有 outbox、没有冲突中心（P3）。两台设备之间只能靠备份/迁移包手工搬。
3. **Obsidian 插件**：界面上的相关文案只承诺「导出 Markdown / 远端笔记库」，没有自动同步。
4. **文件级恢复粒度**：冲突决策是**集合级**，不能逐条勾选或并排比较内容。
5. **凭据的「记住在本设备」**：备份密码只存在本次会话内存，刷新需重新输入。
6. **自动重测连接**：导入凭据后会清除旧检测记录并提供按钮，但按 §1.3 不自动发请求。
7. **扩展真机生命周期验收**与**迁移后 7 天真实使用观察**：未做。
8. **五类云端拉取**：五彩/有道仍是「导入」，不是「拉取」；Cloudflare 旧同步只保留兼容读取，不自动启用。

## 5. 已知限制与体验代价

- **多标签页只警告、不合并**：同一设备开两个标签页时，后写的一方会覆盖先写的（应用会提示「另一个标签页修改了同一份数据…建议重新加载」）。v3 模式下两个标签页的负载是逐字节相同的设备配置、不会触发存储事件，因此**另有一个 `selfhub_v3_activity` 信号（只有库 id/版本/时间戳，不含数据）**让提示依然生效（第 37 批）。真正的并发合并属 P3。

- **冷启动断网不可用**：没有 service worker，离线只保证「已经打开过的页面」继续可用。
- **首屏 JS 约 191 KB gzip**（预算 250 KB；入口 chunk 171 KB）：备份、恢复、资料库、设置、Markdown、迁移栈都按需加载，`index.html` 只预加载入口与核心块。生产产物由 `tests/e2e/production-build.spec.ts`（走 `vite preview`）冒烟验证。
- **容量预警是估算**：5 MB 是主流引擎行为，不是可查询事实；估算与真实上限之间可能仍有误差。
- **列表分页不是虚拟化**：首屏 100 条，滚动性能随已渲染条目增长。
- **v3 模式下保存有额外成本**：每次防抖保存要让适配器确认"库里的记录是否与要写的一致"。已实测并两轮优化：6,600 条记录的库上，无变化保存 **50ms**（原 512ms）、改一条 **191ms**（原 477ms）、首次全量写入 1.7s（`docs/perf-baseline.json` 的 `v3Write`）。剩余成本是"读回变化的集合再逐条比较"，再降需要写入接口接收脏集合（尚未做，见交接记录第 31 批）。
- **性能夹具小于文档规格**：10 万条批注在整包 `localStorage` 上会先撞容量上限，所以实测是下界（见 `docs/perf-baseline.json`）。
